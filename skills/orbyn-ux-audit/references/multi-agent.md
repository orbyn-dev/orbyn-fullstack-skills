# Coordinate read-only audit agents

Resolve the consuming repository's harness before dispatch. Use its native child
roles, models, effort, naming, concurrency and depth; the library's defaults are
not a portable entitlement. Never create sidebar chats unless the user requested
those chats. Keep the coordinator responsible for scope, findings and effects.

## Partition by journeys

A useful batch gives one child account/settings journeys and another search/detail
journeys, with the complete applicable checklist on both. Do not send separate
color, typography and navigation agents across the same app. Add a later targeted
cross-flow consistency pass only when their evidence exposes a shared pattern.
Small or inseparable work can stay solo; disabled delegation stays solo. Report
these limits rather than manufacturing parallel activity.

Write a queue with slice ID, assigned routes/states/environments, child identity,
status, evidence directory and continuation cursor. Statuses are queued, inspecting,
returned, verified, blocked or interrupted. Coordinator verification, not a child's
completion message, determines coverage. Stop dispatch when the authorized time,
resource or harness budget is reached and retain remaining slices as not tested.

## Give each child a bounded brief

Include:

- Exact checkout/build revision, source/instruction roots and flow/matrix rows.
- Applicable checklist and product expectations; unsupported platforms stay excluded.
- Allowed tools, URLs, test identity and actions. Product source/configuration and
  durable data are read-only. Mutating scenarios require an explicitly approved
  disposable sandbox/mock with effects prevented; otherwise report blocked.
- One owned output directory under the approved audit root. Do not write shared
  findings, coverage or manifests. Sanitize captures and use synthetic data.
- Return candidate observations, reproduction, evidence links, rule applicability,
  actual/emulated/static environment and all untested/blocked rows. Distinguish
  confirmed behavior from inferred cause and proposed usability changes.
- Stop conditions, maximum slice size and no further delegation. No installations,
  unrelated browsing, automatic fixes, issue creation, messaging or publication.

Each worker completes only its assigned slice. A resumed agent first reads the
current assignment/revision, reconciles partial artifacts and checks ownership.
Never restart a second writer into the same slice while an earlier one is active.

## Separate mutable execution state

Use isolated browser contexts, test identities, storage and evidence paths only
when the tools actually provide them. Browser contexts isolate client storage,
not shared server data. Do not share an active user's cookies or alter preferences.

When native computer-use tools expose one active tab/window, serialize browser
and OS interactions through one controller. Other children may inspect source or
already captured evidence in parallel; they must not click or navigate that shared
surface. Multiple agents on Windows cannot create real macOS/iOS coverage. Mark
unavailable physical environments not tested.

## Reconcile findings and review

The coordinator owns central IDs and files. Merge by symptom, root component,
trigger and platform/state; retain evidence and affected variants. Similar visuals
alone are not a shared root cause. Preserve existing IDs across reruns; split or
supersede a finding through explicit references rather than silent renumbering.

Use one independent reviewer within a permitted reviewer slot, without recursive
review chains. Prioritize critical/major defects, uncertain rule applicability and
one representative of each repeated root cause. Review may use recorded evidence
when execution would change shared state; label source-only or unreproduced limits.
Have the reviewer challenge reproduction, intended behavior, platform claims,
criteria/exceptions and proposed acceptance checks. Coordinator resolves conflicts;
keep unresolved observations as needs-verification, not confirmed defects.

If no reviewer is available, disclose self-review; do not claim independence. A
review rejection stops unsupported claims, not the rest of the authorized audit.
Return a coverage ledger and complete backlog even when some slices are blocked.
